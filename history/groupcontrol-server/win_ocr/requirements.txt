# ---- GPU(CUDA EP)----
# ⚠️⚠️ 版本钉死,而且下面两组**必须同一个 CUDA 大版本**。
# ORT 的 Windows 轮子是按某个具体 CUDA 大版本编的,ORT 1.28.0 要的是 **CUDA 13**
# (它的 onnxruntime_providers_cuda.dll 依赖 cublasLt64_13.dll)。
# 2026-08-17 实测踩过:配成 -cu12 轮子(装出来是 cublasLt64_12.dll)会报
#   Error loading "...onnxruntime_providers_cuda.dll" which depends on
#   "cublasLt64_13.dll" which is missing. (Error 126)
#   Failed to create CUDAExecutionProvider. Require cuDNN 9.* and CUDA 13.*
# 然后 **静默回落 CPU**(不看 /healthy 的 providers 根本发现不了)。
# 所以升 onnxruntime-gpu 前必须先确认新版本要哪个 CUDA 大版本,同步换下面的 -cuXX。
onnxruntime-gpu==1.28.0

# CUDA / cuDNN 运行时走 pip 轮子,免装完整 CUDA Toolkit。
# DLL 落在 site-packages/nvidia/*/bin,由 ocr_server._add_cuda_dll_dirs() 登记进 DLL 搜索路径。
#
# ⚠️ 命名规则变过(2026-08-17 踩过):**CUDA 13 起 NVIDIA 去掉了 `-cuXX` 后缀**。
#    `nvidia-cublas-cu13` 之类现在是故意构建失败的废弃占位包,装时报
#    "THIS PROJECT ... IS DEPRECATED. Please use 'nvidia-...' instead" 并让整个 pip 事务失败。
#    但 **cuDNN 保留后缀**(它的版本号独立于 CUDA,后缀用来标它是给哪个 CUDA 编的)。
#    验收标准:装完 site-packages\nvidia\cublas\bin 里应是 `cublasLt64_13.dll`(带 13,不是 12)。
nvidia-cuda-runtime
nvidia-cublas
nvidia-cufft
nvidia-curand
nvidia-nvjitlink
nvidia-cuda-nvrtc
nvidia-cudnn-cu13
