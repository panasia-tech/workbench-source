# Changelog

## 未发布

- 巡航台增加单实例锁：同一工位重复打开时第二个进程直接退出，并把已开的窗口叫到前面；避免两个进程同时写 `xianyu-electron.json` / `xianyu-task-center.json` 造成 Windows `EPERM rename`。
- 群控/ERP 接口返回 401 时不再把「超时 / 未登录」留在会话页：主进程统一清本地登录态并通知所有窗口，渲染层提示「登录已过期，请重新登录」后自动回登录页；本地配置写盘失败也照样回登录页，退出登录不会被文件锁卡死。
- 本地配置写盘遇到 `EPERM/EBUSY/EACCES` 时按 0/120/300/600ms 自动重试，仍失败则给出「关闭其他巡航台实例 / 加入杀毒白名单」的明确提示；任务中心的 `xianyu-task-center.json` 同样走这套重试。
- 修复行情工作台连不上 ERP 接口：ERP 服务器地址从写死在主进程改为配置项（登录页和「库存 API 连接」都能改，默认仍是 `http://127.0.0.1:8000`），并在 store 入口统一校验，空值/写错的地址不再被静默保存。
- 库存读取不再需要第二套凭据：服务端 `_inspector_filter` 放行 `CRAWLER` 看全部在库型号（`_hide_cost` 同时对它屏蔽成本价，工作台的采购价本来就来自 Excel），工作台改用自己的登录账号读库存。此前 CRAWLER 落在「只看自己验过的货」的兜底分支，而爬虫从不验货，接口稳定返回 200 + `total: 0`——鉴权通过、数据为空，现场就表现为"连不上 API"。回写商品名称仍只放行 ADMIN/仓管，作为可选配置项保留；界面文案与代码注释里「ADMIN/WAREHOUSE」的错误说法一并纠正。
- 用自身登录态读库存时拒绝接受空结果：「200 + 0 条」既可能是真空库存、也可能是服务端尚未放行该角色，两者无法区分，而误判会清空整份 API-SPU 快照；这条路径下改为报错并保留上次快照。
- MCP 兜底通道此前必然被拒：白名单只认主域，而 ERP 实际把 MCP 挂在 `api.` 子域，且缺尾斜杠会被服务端 307、又撞上禁止跟随重定向。现在白名单跟随配置的服务器（含 `api.` 子域）并自动补齐尾斜杠。
- WMS 同步失败原因透传到界面：改为抬出服务端 `detail`（如「非管理员账号」）而不是 axios 的「Request failed with status code 403」，auto 模式两条路都断时同时给出 REST 与 MCP 的原因；凭据脱敏保持不变。
- 行情工作台新增应用内代码热更新：安装包入口改为 `loader.js`，优先加载 `userData/code/` 下的新代码，发版只需上传 `out/` 与清单，不必重下安装包。逐文件 MD5 校验、整目录原子替换、保留上一版可回滚；加载失败或启动未就绪会自动隔离坏版本并回退内置代码。巡航台构建不带 `code-version.json`，保持整包分发。

- 新增可选的 Caddy Compose override 和无密钥 Caddyfile 示例，适用于公司 Caddy 已占用 80/443 的服务器；override 只接入明确指定的外部 Docker 网络，并把仓库 Nginx 放入 `standalone-nginx` profile，不会修改或替换现有网关。
- `server:deploy-compose` 现在支持 `XIAN_YU_GATEWAY=caddy`：跳过仓库 Nginx TLS 文件、校验外部 Caddy 网络，并只启动 `xianyu-server`，避免一键部署误抢公司 80/443；默认 Nginx 路径保持不变。
- `server:deploy-compose` 新增 `XIAN_YU_SERVER_IMAGE` 预加载镜像路径：先校验目标主机已有架构匹配镜像，再使用 `--no-build` 启动，避免上线时重复下载 Camoufox；未设置时继续使用原有 `--build` 路径。
- 预加载镜像门禁现在实际比较宿主 `uname -m` 与 Docker 镜像架构（amd64/arm64），错架构会在 Compose 启动前 fail-closed；新增错架构阻断回归。
- 生产服务器直接依赖 `ws` 升级到 `8.21.3`，并通过 BitBrowser 模拟生命周期/鉴权/显示回归；保留 Fastify/fast-uri/xlsx 的独立兼容性评估，不运行高风险强制升级。
- 当前提交已用 Docker `linux/arm64` 与 `linux/amd64` 分别构建并启动验证：非 root、Camoufox CLI/浏览器运行时、`/health`、`/ready` 和 H5 adapter 均通过；fixture provider 不代表真实闲鱼账号或公司服务器。
- 同一生产镜像的 `linux/arm64` 与 `linux/amd64` 均完成 Camoufox CLI 0.7.3 实际浏览器运行时 smoke：打开公开 `example.com`、读取无障碍快照、生成非空截图并关闭；证据在外置盘，仍不替代公司 Linux/真实闲鱼/WMS/员工 GUI 验收。

- 目标 ECS 另以临时命名卷完成两次生产容器启动，bootstrap 管理员在删除/重建容器后仍可登录，验证 SQLite 账号数据跨容器重启保留；正式数据卷仍需上线时按备份/回滚合同验收。

- 删除库存商品页已不再适用的“待补 69 码”板块，并移除对应候选队列、人工回写 IPC、预加载桥接、写回审计和专用回归脚本；正常 API 条码身份读取保持不变。
