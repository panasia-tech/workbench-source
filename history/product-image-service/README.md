# Product Image Retrieval Service

独立的品牌+型号产品图片检索服务。服务会优先使用官方页面和已配置的合法 API，再使用公开网页/社区 Provider；缺少凭证时自动降级，不通过验证码、风控、访问控制、付费墙或私人内容。

## 快速启动

```bash
cp .env.example .env
# 至少修改 ADMIN_PASSWORD、ADMIN_SESSION_SECRET、CREDENTIAL_ENCRYPTION_KEY
# Docker 对外提供服务时把 HOST 改为 0.0.0.0，并把 ADMIN_AUTH_MODE 改为 required
# 使用公网隧道时同时配置 EMPLOYEE_ACCESS_TOKEN，避免员工工作台匿名暴露
docker compose up -d --build
```

API 文档：`http://127.0.0.1:8090/docs`

管理后台与图片检索工作台：`http://127.0.0.1:8090/admin`

Wallpaper H5 管理台（实时读取外置盘、图片目录和运行器）：`http://127.0.0.1:8090/wallpaper`

10 秒 / 100 帧电脑显示端：`http://127.0.0.1:8090/wallpaper/player`（也可用 `https://127.0.0.1:8443/wallpaper/player`）。电脑页面只负责全屏等待和播放 100 张图片；iPhone Safari 通过 `http://127.0.0.1:8443/wallpaper/remote` 连接页面显示的 6 位配对码，点击“开始录像”后，手机摄像头录制 10 秒，并在实时取景过程中每 100ms 直接抓取一帧，自动得到 100 张 JPEG 并打包下载。手机摄像头页面必须使用 HTTPS。

Wallpaper 管理台的状态接口为 `GET /v1/wallpaper/status`，图片列表为 `GET /v1/wallpaper/images`，图片文件通过 `GET /v1/wallpaper/files/{filename}` 提供；管理员可用 `POST /v1/wallpaper/start` 和 `POST /v1/wallpaper/stop` 控制已配置的运行器。页面只展示允许的图片格式，视频项目直接跳过。若服务进程没有 `STEAM_API_KEY` 环境变量，页面会明确显示“待配置 API Key”，不会假报运行中。

打开后台后，可以直接输入例如 `AOC 24G2`，页面会轮询任务并整理显示图片、来源、尺寸、置信度、图片分类和淘汰数量；API 默认最多返回 20 张，后台可选择 30、50、100、300 或 500 张。首轮检索提供严格、平衡、宽松三档，结果分成正式图片池和可人工复核的备选池；模糊命中的图片会保留预览，员工或管理员可一键在两个池之间互划。页面还会列出本次实际使用的查询策略和新增检索量，方便员工追踪每次扩容来源。

管理员可以在“管理设置 → 屏蔽网站”维护域名黑名单。添加 `example.com` 后，该域名及其子域名的候选不会进入正式图片池、模糊池或淘汰预览池；任务诊断会记录命中的域名和拦截数量。屏蔽名单只影响之后启动的新任务，取消屏蔽后即可恢复检索。

后台只保留一套任务归属：接口返回 `lane=good|bad|history`，所有页面都使用这一个字段。好的列表显示排队中、处理中和已完成任务，包含排队位置、当前阶段、完成百分比、已用时间和动态预计剩余时间；重试任务会在顶部并有分隔线。坏的列表显示爬取失败（`failed`）和审核标记“需处理”（`completed + review_status=needs_changes`）的任务，原因、名称历史和处理入口集中在这里；审核通过或重试重新入队后会回到好的列表。取消任务只进入 `history` 归档，不会混进好/坏工作队列。

坏任务通过 `GET /v1/images/tasks?bucket=bad` 查询；正常任务通过 `GET /v1/images/tasks?bucket=good` 查询。点击“重新搜索”可以先编辑名称，提交后同一个任务会从坏的列表移除并回到好的列表的最上方重试区。活动任务、坏任务列表和批量卡片刷新均按任务/批次原地更新，已展开的列表和滚动位置不会被定时刷新打回表头。

批量卡片的“好的列表”只展示已完成且未标记需处理的子任务，“坏的列表”展示失败或审核标记需处理的子任务，不再把排队和处理中混进异常；坏列表会逐条显示未完成/需处理原因，例如 Provider 超时、限流、没有图片通过型号/质量校验或员工审核备注。员工工作台也使用同样的好/坏双列表，审核通过后任务自动回到好的列表，详情显示同一原因，方便判断是等待重试还是人工处理。

任务完成表示检索流程已经结束，不再由正式图片数量硬判失败；无候选或 Provider 全部故障仍会失败。`diagnostics.formal_shortfall` 仅作为相对目标的提示，`candidate_images` 用于人工复核。失败任务可以在未完成列表、历史任务或结果详情中点击“重新搜索”，重试前可编辑检索名称；批次卡片也提供“重试失败任务（N）”，只会重新入队失败子任务，不会重复已完成任务。每次重试会把当前正式、模糊和淘汰池保存到 `diagnostics.retry_snapshots`，新一轮单独生成，原失败原因和名称历史仍会保留；结果详情会提供“历史尝试候选池”预览。重试同时受 TASK_RETRY_LIMIT（默认 3 次）限制。

任务区下方的“历史任务”会保留已结束任务的“查看结果”入口。打开已完成任务后，可以直接查看正式图片池、模糊候选池和淘汰候选预览池；已取消或失败的任务会显示对应的无结果说明。

任务区还提供“批量导入 Excel”入口。上传首个工作表中含“品牌+型号 / SPU编码”（或分开的“品牌”“型号”）列的 `.xlsx`/`.xlsm` 文件后，每个非空型号会生成一个带行号和 SPU 的子任务；批次卡片会显示总任务数、已完成数、完成百分比、处理中、排队、失败和取消数量，并提供“好的列表”和“坏的列表”两个独立入口，可分别查看结果或重试失败子任务。

搜索框支持自动品牌/型号扩展。例如 `ROG PG27UQR` 会加入 `ASUS ROG PG27UQR` 和 `华硕 ROG PG27UQR`，`小米空气净化器4lite` 会加入 `Xiaomi Smart Air Purifier 4 Lite`。语言下拉框可以限定 15 种语言之一；市场平台会依据 `config/market_platforms.json` 标记为 active、conditional 或跳过。词库维护方法见 [`docs/QUERY_PLANNER.md`](docs/QUERY_PLANNER.md)。

登录管理区后，页面下方的“平台编排中心”会按平台显示项目组件数量、内置阶段、外部仓库、健康状态和启停按钮。例如淘宝、快手、Mercari、Facebook Marketplace 都有独立的组件轨道。编排清单和新增方法见 [`docs/ORCHESTRATION.md`](docs/ORCHESTRATION.md) 与 [`config/orchestration.json`](config/orchestration.json)。

搜索工作台默认使用 `全部并分栏`：商品图、实拍图和未分类图片分别统计。也支持 `只要实拍图` 和 `只要商品图`；实拍图模式只接收已被适配器标记为 `real_photo` 的候选，不会因为未分类候选而误报实拍图。

创建任务：

```bash
curl -X POST http://127.0.0.1:8090/v1/images/search \
  -H 'content-type: application/json' \
  -d '{"query":"sonos era300","limit":20}'
```

服务返回 `task_id` 后，使用 `GET /v1/images/tasks/{task_id}` 查询。图片会复制到本地 `storage/` 并通过 `/files/{sha256}.ext` 提供访问地址。

查看当前队列：

```bash
curl http://127.0.0.1:8090/v1/images/tasks
```

按好/坏列表查询：

```bash
curl 'http://127.0.0.1:8090/v1/images/tasks?bucket=good&limit=200'
curl 'http://127.0.0.1:8090/v1/images/tasks?bucket=bad&limit=200'
```

取消排队或正在处理的任务：

```bash
curl -X POST http://127.0.0.1:8090/v1/images/tasks/{task_id}/cancel
```

重新排队一个失败任务：

```bash
curl -X POST http://127.0.0.1:8090/v1/images/tasks/{task_id}/retry \
  -H 'content-type: application/json' \
  -d '{"query":"ASUS ROG XG259CMS"}'
```

重新排队一个批次中的全部失败子任务：

```bash
curl -X POST http://127.0.0.1:8090/v1/images/batches/{batch_id}/retry-failed
```

任务详情中的 `progress` 字段包含 `phase`、`percent`、`elapsed_seconds`、`estimated_seconds` 和 `eta_seconds`；取消后的任务状态为 `cancelled`。

Provider 遇到连接池超时、连接中断或读取/协议错误时会按 `PROVIDER_RETRY_ATTEMPTS` 做有限重试。重试耗尽且没有候选时任务会标记为 `failed`，并在明细的错误提示与诊断中保留 Provider 原因；只要检索产生了可供复核的候选，即使正式池暂时较少也会进入已完成的人工划分流程。

请求也可以指定图片模式和平台范围：

```bash
curl -X POST http://127.0.0.1:8090/v1/images/search \
  -H 'content-type: application/json' \
  -d '{"query":"AOC 24G2","limit":100,"image_mode":"all","platforms":["taobao","amazon","mercari"]}'
```

## 凭证

凭证不是单一机器人密码，而是按平台区分的 API Key、OAuth Client、Access Token 或用户主动提供的合法登录态。通过后台保存的值使用 Fernet 加密存储；API 永远不返回明文。也可以直接使用 `.env`，但 `.env` 不得提交 Git。

Provider 的当前能力、申请入口、fallback 和限制见 `docs/CREDENTIALS_REQUIRED.md` 与 `docs/PROVIDER_STATUS.md`。

## 本地开发

```bash
python3.12 -m venv .venv
. .venv/bin/activate
pip install -e '.[dev]'
ADMIN_AUTH_MODE=local_dev ALLOW_SYNTHETIC_DNS=true uvicorn app.main:app --reload --port 8090
pytest -q
ruff check app tests scripts
```

`ADMIN_AUTH_MODE=local_dev` 只允许本机管理后台免登录；远程部署请改为 `required`。`ALLOW_SYNTHETIC_DNS=true` 只适用于当前受控网络的本地验证，生产环境必须保持 `false`。

Playwright 是最后 fallback，默认关闭；如明确需要，在隔离环境安装 `pip install -e '.[browser]'` 并单独安装浏览器。

## 质量和安全边界

- 只有通过图片魔数、Pillow 解码、尺寸、像素和型号证据检查的候选才会返回。
- SHA-256 与 pHash 用于去重；同图优先保留高置信、高分辨率来源。
- 三档首轮策略、后台可配置的证据门槛/校验倍数，以及正式/备选图片池人工互划；旧 20 张规则仅保留在历史变更记录中。
- 返回数量为 50/100/300/500 时会按平台/来源交错排序，尽量避免结果被单一来源占满；300/500 会额外启用大批量检索波次。
- 长型号或地区后缀明显的稀缺 SKU 会自动启用 S-04 追加检索；300/500 请求会记录 S-06 大批量追加检索。两者都受查询轮次、候选数和下载并发上限约束。
- 实验分支还会记录 S-07 动态近邻型号/新来源域名扩展，以及 S-08 宽松模糊池留存；S-08 只扩大模糊池，不降低正式池门槛。
- 100/300/500 档位还可启用 S-09 深度图库展开和 S-10 原图 URL 变体恢复；S-10 只尝试公开图片 URL 的尺寸标记，不访问新主机。
- 目标模式还会启用 S-11 同站图库/评论页一跳扩展和 S-12 页面嵌入式媒体清单提取；普通 30 张搜索不启动这些长任务策略。
- 目标模式实验还会记录 S-13 品牌/尺寸/品类家族模糊池、S-14 Bing 后续结果页、S-16 候选验证蓄水池、S-17 型号写法扩展、S-19 正式池外溢候选留存、S-20 Bing 长尾分页、S-21 深度验证水库、S-22 来源页第二跳深挖、S-23 完整型号查询矩阵、S-24 多语言完整型号来源矩阵、S-25 型号家族视觉近邻矩阵、S-26 核心候选优先评估和 S-27 超深验证水库；这些策略只增加可检查候选，不降低正式池门槛。
- 普通请求的淘汰候选预览默认最多保存 300 张、模糊池默认最多保存 500 张；100/300/500 目标模式额外启用 S-18，分别使用 `TARGET_MAX_FUZZY_PREVIEWS=1000` 和 `TARGET_MAX_REJECTED_PREVIEWS=1000` 的千张级预览蓄水池。两类预览仅保留已安全下载并成功解码的图片，不进入正式 API 结果。
- S-20 目标模式会把 Bing 同一查询从原来的 3 页继续读取到第 5 页；第 4/5 页单独记录，便于区分长尾候选的真实贡献。它会增加任务耗时，只在 100/300/500 目标档位启用。
- S-21 极限目标模式把候选验证倍率从 20 倍提升到 30 倍，模糊池和淘汰池上限提升到 3,000/3,000；适合人工复核优先的长任务，不建议普通搜索使用。
- S-22 目标模式会从首跳相关页面继续挖第二跳图库和评测页，新增候选统一标记为 `deep_related_page`，并继续执行图片安全和型号证据校验。
- S-23 目标模式会将完整品牌+型号与已发现来源域和买家意图词交叉查询，默认最多 64 条矩阵查询、执行 4 轮；它会增加过滤池规模，也可能带来更多需要人工复核的长尾。
- S-24 将完整型号与 15 种语言的评测、晒单、开箱和用户图片意图词交叉到已发现来源域；S-25 使用同前缀 SKU 做宽召回，品牌相符但型号不完整的安全图片只进入模糊池。
- S-26 在目标模式中调整验证顺序：原始查询、完整型号矩阵和多语言完整型号矩阵优先，型号家族近邻随后验证。它不减少模糊/淘汰池，只降低扩展噪声挤占正式池验证槽位的概率；每次任务会在 `diagnostics.search_strategy_log` 中标注。
- 目标模式使用流式图片验证和有界候选蓄水池，避免全量长尾候选常驻内存；实验参数过大仍可能耗时很长，部署前应先做目标服务器资源测试。
- S-27 将目标模式验证窗口默认提高到 50 倍，最多实际验证 5,000 个候选；它适合需要大量人工复核图的长任务，普通 20/50 张任务不启用。
- S-29 将目标模式的模糊/淘汰预览容量提高到 6,000/6,000；它只解除安全预览数量截断，不改变图片验证规则。目标任务可能更慢、返回诊断更大，普通搜索仍使用 500/300 上限。
- S-30（V18 实验）将目标模式候选蓄水池提高到 12,000、实际评估上限提高到 8,000，并把 S-27 的 50 倍验证窗口扩到 80 倍；它只增加长尾候选进入三池的机会，不放宽正式池门槛。一次 AOC 24G10ZNE 实测达到正式 16、模糊 1,104、淘汰 5,816，耗时约 34 分钟，因此只适合作为后台深挖任务，不直接用于普通搜索。
- S-31（V19 实验）把目标模式候选蓄水池提高到 20,000、评估上限提高到 12,000、预览池提高到 12,000/12,000，并按核心/近邻/宽召回三层均匀保留；它只增加长尾候选进入三池的机会，不放宽正式池门槛。完整目标实验耗时超过 55 分钟未落库，短 smoke 已验证三层诊断和任务落库，因此 V19 仍是实验分支，不直接用于普通搜索。
- S-32（V20 实验）让宽召回长尾候选先走“安全图片预览”路径：只做公开下载、魔数/Pillow、尺寸和去重校验，再按品牌/型号相关度进入模糊池或淘汰预览池；核心/近邻候选仍走完整型号证据链，正式池门槛不变。受控 smoke 得到正式 10、模糊 168、淘汰 303，共 471 张安全预览，其中宽召回快速路径解码 344 张；完整目标实验按用户要求提前停止，未计入对照。
- S-33（V21 实验）在已发现的公开来源域内旋转品牌、品类、型号和买家图片意图词；它扩大来源发现，不绕过页面权限，也不改变正式池证据门槛。AOC smoke 得到正式 7、模糊 64、淘汰 498，共 569 张安全图片，但查询约 10 分钟，低相关淘汰图明显增加。
- S-34（V22 实验）从已发现的同品牌/品类公开页面继续扇出图库、评论页和相关页的图片；只读取公开 HTML，不执行脚本。小矩阵增加了 55 个页面候选，但没有带来可确认的安全预览增量，因此保留为可选扩展，不作为默认主策略。
- S-35（V23 最终实验）在主评估窗口之后单独追加宽召回候选，只做下载、魔数/Pillow、尺寸和去重校验；追加结果只能进入模糊/淘汰预览池。最终受控 smoke 主窗口 600、追加 300，得到正式 11、模糊 150、淘汰 668，共 829 张安全图片，其中 S-35 贡献 35 张模糊和 201 张淘汰预览。默认追加量为 1,200，可通过 `TARGET_FAST_TAIL_EVALUATION_CANDIDATES` 调低或提高。
- 下载器拦截本机、私网、链路本地、保留地址和云元数据地址；限制重定向、超大图片和异常内容。
- 默认只标记水印，不移除第三方版权/署名水印。
